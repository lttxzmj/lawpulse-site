让 AI 助手直接查到现行法条：给律师的 MCP 入门

进阶篇 · 阅读路线第 6/7 站 · 2026-11-07 发布 · 完整路线

直接问 AI 法律问题，最大的坑是它凭「记忆」回答：法条背串、条号过时、整条编造（核查方法见这篇）。MCP（Model Context Protocol）解决的正是这件事：它是一个开放协议，由 Anthropic 发起、主流 AI 客户端陆续支持，让 AI 助手在回答之前先去调用外部数据源——查到真实条文原文，再基于原文回答。

一句话说清区别：没接 MCP 的 AI 在背法条，接了 MCP 的 AI 在查法条。

需要准备什么

  • 一个支持 MCP 的 AI 客户端（Claude Desktop、Cursor 等，入口位置以各客户端文档为准）；
  • 电脑上装有 Node.js（nodejs.org 下载安装即可，配置里用到它的 npx 命令）。

十分钟配置：以中国法律 MCP 服务器为例

以我们维护的开源服务器 chinese-law-mcp 为例（数据取自 CC0 开放语料，1500 余部现行法律、司法解释与行政法规，官方来源逐部核对）。在客户端的 MCP 服务器配置里加入：

{
  "mcpServers": {
    "chinese-law": {
      "command": "npx",
      "args": ["-y", "github:lttxzmj/chinese-law-mcp"]
    }
  }
}

保存后重启客户端，AI 就多了三个查法条的工具：

  • search_laws：按名称搜法律（「民法典」「劳动合同」）；
  • get_article：取指定条文原文（如民法典第 577 条），带章节位置、施行日期和可引用的网页链接；
  • search_in_law：在某部法律全文里按关键词检索条文。

配置完成后直接用自然语言提问，比如「用工具查一下民法典里关于违约责任的规定」，AI 会自己调用检索、拿到原文再作答，每条结果附可点开核对的来源链接。

两个必须知道的边界

第一，装 MCP 服务器等于在本机运行第三方代码，只装来源可信的。 装之前看三件事：代码是否开源可审（本例 MIT 协议开源）、数据来源是否可溯源（本例为官方文本整理的 CC0 语料）、有没有多余的权限和上传行为（本例只读检索、无遥测）。来路不明的服务器，再方便也不装。

第二，MCP 解决「查得到、查得真」，不解决「用得对」。 条文找对了，适用判断仍然是你的工作；正式引用以官方公布文本为准，这一点工具输出里也会自带提示。

不想折腾配置的话

MCP 适合已经在用 Claude、Cursor 这类客户端的人。如果只是想要「AI 回答带可核查的法条引用」，开箱即用的工具是更省事的路：全量法库内置，AI 引的每条法条自动回库核对。两条路解决的是同一个问题，按你现有的工作环境选。
